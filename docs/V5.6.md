# V5.6 · Herramientas reproducibles y archivos clasificados

Las herramientas estaban repartidas entre la raíz, `scripts/` y el
laboratorio cartográfico; las auditorías mezclaban informes regenerables con
resultados versionados. V5.6 reúne sus entradas, documenta un entorno Python
comprobable y conserva explícitamente las fuentes y revisiones aceptadas.

## Organización

Se trasladan **50 archivos de herramientas**, manteniendo sus funciones:

- Auditorías → `scripts/audits/`.
- Generadores de catálogos, árbol, sitemaps e HTML → `scripts/generate/`.
- Generadores, ensambladores y mediciones cartográficas → `scripts/cartography/`.
- Utilidades compartidas de HTML, seguridad y rutas → `scripts/lib/`.

`scripts/schema/` conserva los contratos y comparadores. Se actualizan
imports, pruebas, comandos npm, CI y documentación vigente. `prebuild` sigue
el orden original mediante `audit:build` y `generate`. Los visores y las capas
cartográficas aceptadas permanecen en `prototypes/euv-locations/`, incluidos
los utilizados por el sitio; los scripts ya no comparten esa carpeta.

## Python y clasificación

`.python-version` fija **3.12.14**. El lock incluye Shapely **2.2.0**,
svgpathtools **1.8.0**, NumPy **2.5.4**, SciPy **1.18.1** y svgwrite **1.4.3**,
con hashes oficiales de sus ruedas. La instalación se realiza en un entorno
aislado y exige hashes. Python queda fuera del build de Vercel.

La comprobación regenera los inventarios en una copia temporal, usando otro
directorio de trabajo: **7.672 paths**, **7.641 celdas visibles** y **2.463
celdas regionales** reproducidos. Las medidas almacenadas a siete decimales
admiten `2e-7` de diferencia absoluta; IDs, visibilidad y estructura deben ser
idénticos. No se modifica el cálculo geométrico original.

La [clasificación](artifacts.md) y el [catálogo](artifact-catalog.json) registran
**41 archivos** cartográficos, laboratorios y resultados revisados. La nueva
auditoría bloquea entradas ausentes y archivos cartográficos sin clasificar.
Tres informes se trasladan, con contenido idéntico, a
`docs/reports/reviewed/`. La continuidad documental conservada sigue en
`docs/atlas-continuity-audit.json` y `.md`. Los diagnósticos nuevos se escriben
en `.cache/audits/`; el build ya no sobrescribe estas instantáneas.

`EADE_MAP_DATA_DIR` permite a Python y JavaScript usar una copia de trabajo.
Las fuentes, selecciones y revisiones manuales se conservan; los generadores
históricos no se convierten en una publicación automática. El recorte mundial
completo requiere la exportación original del usuario, ausente del repositorio;
la comprobación de inventarios usa exclusivamente los SVG versionados.

## Validación

- 410 pruebas y 29 comprobaciones de hidratación de fichas reales.
- 3.528 fichas HTML verificadas sin errores.
- Regresiones V5 de datos, mapas completos y personales en 1200–1800 y páginas públicas: cero diferencias, sin actualizar la base.
- Inventarios geométricos reproducidos con el entorno fijado; Python y extracción cartográfica JavaScript probados en copias aisladas.
- Contratos, clasificación y seguridad sin incidencias; dependencias npm sin vulnerabilidades.

CI añade la instalación Python con hashes, la comparación geométrica y una
comprobación de que la ejecución deja intactos mapas, instantáneas revisadas
y bases. La interfaz, las relaciones, los mandatos y las superficies del Atlas
se conservan.
