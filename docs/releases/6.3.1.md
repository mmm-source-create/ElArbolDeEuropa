# 6.3.1 · Hidratación después del primer pintado

Preparada sobre la 6.3.0.

Tras la 6.3.0, en un navegador real el retrato de una ficha se pinta con el
primer pintado de la página (1,3 s en la prueba, frente a unos 2 s antes). Pero
PageSpeed seguía dando un LCP simulado de 6,5 s en móvil: en su carga de
referencia, rápida, la página termina de cargar antes de pintarse, el código de
hidratación se ejecutaba enseguida y retrasaba ese primer pintado 1,1 s; la
simulación de un móvil lento multiplica ese tiempo.

`main.jsx` espera ahora, además de a la carga de la página, a que se haya
pintado un fotograma antes de hidratar (`requestAnimationFrame` y después
`setTimeout`). Si el navegador no tiene `requestAnimationFrame`, espera 16 ms.

## Comprobaciones

- `tests/v6-3-0-release.test.mjs` y `tests/boot-v2152.test.mjs`.
- `npm test` y regresión de datos sin diferencias.

## English

Hydration now waits for a painted frame as well as for the page load, so the
hydration code no longer delays the first paint of a static page.
