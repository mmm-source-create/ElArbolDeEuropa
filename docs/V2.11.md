# V2.11 — Sucesiones explicadas

Actualización incremental sobre la V2.10 con sus retoques previos. El ZIP contiene únicamente archivos añadidos o modificados. Las cuatro suites de pruebas de versiones anteriores se incluyen porque faltaban en el repositorio de GitHub revisado.

## Cambios del producto

- **55 relevos explicados** en fichas territoriales: motivo, predecesor, sucesor, contexto familiar y referencias.
- **Cuatro crisis desplegables**: Avesnes–Dampierre, Brabante en 1355–1357, Jacoba de Baviera y Güeldres en 1371–1379. Sus candidatos tienen fundamento, línea familiar, resultado y enlace al Atlas.
- Fechas diferenciadas de acceso, gobierno, coronación o toma de posesión cuando hay información específica. Ejemplos: Alberto de Baviera, Juana de Brabante y Enrique VII de Inglaterra.
- **39 personajes nuevos con minibiografía**. La base alcanza **2257 personas y 746 minibiografías**.
- **Zelanda** se incorpora como condado propio. Siete fichas históricas enriquecidas: Flandes, Henao, Holanda, Zelanda, Brabante, Limburgo y Güeldres.
- Ampliación de gobiernos y filiaciones de Avesnes, Dampierre, Brabante, Wittelsbach, Jülich y Egmond. Corrección del ordinal de Guillermo I de Henao, que fue Guillermo III de Holanda; conserva su URL anterior y los nombres alternativos.
- Güeldres distingue condado y ducado. Los filtros incluyen Zelanda en su contexto neerlandés e imperial.
- Se distinguen las cesiones de Carlos V de 1555 y 1556, la reclamación de Felipe II sobre Holanda y Zelanda tras 1581 y la soberanía compartida de Alberto e Isabel Clara Eugenia desde 1598.
- El motor de desafíos utiliza `gobiernos` como fuente principal y evita preguntas de sucesión única con lagunas, rivales o corregencias.

La selección de relevos no pretende explicar todavía todas las sucesiones de la base. Los parentescos se calculan a partir de filiaciones registradas, con un recorrido limitado; no encontrar un vínculo no prueba que no exista. Las genealogías de las crisis se escriben editorialmente y el auditor comprueba cada enlace de progenitor a descendiente.

La sucesión continúa **dentro de la ficha territorial**. Se conservan la cartografía, la paleta, la cabecera, el aviso móvil, las historias existentes y los botones de recomendaciones. No se añaden retratos ni recorridos guiados. Las referencias se integran en la bibliografía compartida.

## Revisión de las siete sugerencias

| Sugerencia | Diagnóstico y decisión |
| --- | --- |
| Falta README | Confirmado en GitHub. Se añade onboarding, comandos, mapa del código, publicación y derechos. |
| No hay tests | En la copia local había 34 pruebas; faltaban sus archivos en GitHub. Se incluyen y amplían hasta 52, con render de componentes, rutas, geometría y quiz. |
| Falta CI | Se entrega GitHub Actions para PR y `main`. Hace falta subir el workflow y exigir su check en la protección de rama para bloquear fusiones. No se han cambiado esos ajustes remotos. |
| Dependencias en `latest` | Se fijan las versiones ya instaladas y probadas; se conserva el lockfile y se adopta Node 24. No se actualizan librerías. |
| Monolitos | Se separan las rutas de `App`, los cálculos geométricos de `treeLayout` y las reglas de gobiernos del motor de desafíos. Las nuevas explicaciones y crisis tienen componentes y datos propios. Dividir por completo `ExplorerView` y los grandes catálogos queda para un cambio específico, sin reabrir ahora el trabajo de rendimiento. |
| Falta licencia | Ya existía una decisión explícita en `COPYRIGHT.md`: todos los derechos reservados. Se enlaza desde el README y se refleja como `UNLICENSED`; no se impone una licencia nueva. |
| Baja visibilidad en búsquedas | El 12/09/2026 el `robots.txt` publicado respondió HTTP 200, permitió rastreo y anunció `sitemap-full.xml`. También se obtuvo el sitemap público. Esto no permite concluir qué está indexado; el README describe el diagnóstico en Search Console. No se han hecho búsquedas generales ni promesas de posicionamiento. |

## Validación

Resultados de esta entrega:

- `npm test`: **52 pruebas, 52 correctas, 0 fallos**.
- Instalación independiente con caché separada completada; las 52 pruebas también pasan sin depender de metadatos generados previamente.
- **Prueba del ZIP aplicado sobre el código anterior**: `npm ci`, `npm test` y `npm run build` completados correctamente en una carpeta separada. Las auditorías posteriores a la regeneración también pasan sin errores ni advertencias.
- `npm run prebuild`: completado como parte de `npm run build`.
- `npm run build`: compilación de producción completada. Vite conserva el aviso de bundles superiores a 500 kB; no se ha ocultado ni se ha emprendido una reestructuración de rendimiento.
- Auditoría de personas después de regenerar: **0 errores, 0 advertencias, 1191 observaciones informativas**.
- Auditoría territorial: **0 errores, 0 advertencias, 10 observaciones informativas**. Registra 23 huecos cronológicos de al menos 50 años y una candidatura de alta prioridad ya pendiente: Sratsimir de Kran. No se rellenan con gobiernos inventados.
- Auditoría dinástica y documental: **0 errores**.
- Auditoría de sucesiones: **55 relevos, 4 crisis, 0 errores**. Valida mandatos concretos, entidades, motivos, referencias, fechas, identificadores y filiaciones de los candidatos.

Los avisos de metadatos ausentes o desactualizados que puede emitir la primera auditoría de un parche desaparecen al regenerarlos. Los informes de trabajo no forman parte de los archivos fuente del ZIP.

El servidor de prueba se detuvo al terminar.

La revisión visual de esta versión se realizó sobre la compilación de producción, conforme a la excepción solicitada para V2.11. Se revisaron la sección territorial, los desplegables de reclamaciones, las fechas y el formato móvil (390 × 844). En móvil el documento no desborda horizontalmente. Se comprobó el filtro de disputas (19 → 22 mandatos en Henao), el salto que abre una crisis, la selección de Jacoba en el Atlas, Zelanda en su grupo de filtros y la generación visible de una pregunta del desafío. No aparecieron errores de consola en estas comprobaciones. Se ajustó el margen de los saltos internos para respetar la cabecera fija en móvil. Las revisiones visuales con servidor local no quedan autorizadas automáticamente para actualizaciones futuras.
