# V2.12.2 — Fichas estáticas e hidratación

Actualización incremental sobre la V2.12 entregada. El ZIP contiene únicamente archivos nuevos o modificados. Extrae su contenido en la raíz del proyecto, conservando las carpetas y los archivos ocultos. No hay archivos que eliminar.

```sh
npm ci
npm test
npm run build
```

Se mantiene Node 24. `jsdom` es la única dependencia directa añadida, fijada a la versión 30.0.1 como dependencia de desarrollo. Sirve para las pruebas de DOM e hidratación y no forma parte de los bundles publicados. El generador funciona en Node con React y Vite; no usa un servidor local, Chromium, Playwright ni descargas de páginas.

## Qué cambia

Las fichas individuales de personas, dinastías y territorios contienen su HTML y sus metadatos desde la primera respuesta. El proceso usa los mismos componentes React que el navegador y los JSON producidos por `prebuild`. El sitemap regenerado determina las rutas, sin mantener una segunda lista de entidades.

El navegador recibe un JSON inicial escapado dentro de cada documento y utiliza `hydrateRoot` para activar sus controles conservando el HTML. No repite la descarga del JSON de la ficha. El arranque con `createRoot` continúa disponible para las rutas dinámicas y cuando no existe un documento estático válido.

Los títulos, descripciones, canonical, OpenGraph, Twitter y alternates se calculan en un módulo compartido. Se imprimen en el `<head>` durante la compilación y se reutilizan al hidratar. El alias dinástico registrado conserva su canonical de destino.

El manifiesto de Vite permite incluir los estilos necesarios en el `<head>` y precargar los módulos de las fichas. La selección activa de la cabecera recibe la ruta explícita. El aviso móvil respeta la preferencia de sesión sin cambiar el HTML que React espera inicialmente.

El acceso al Atlas de la ficha personal es ahora un enlace con URL real, conservando el aspecto del botón. Se ajusta la especificidad de su regla de color para mantener el texto claro. No cambian las dimensiones, tipografías, paleta ni los retoques de dinastías de la V2.12.

## Alcance y rutas

| Ruta | Respuesta inicial |
| --- | --- |
| `/es/persona/:slug` | Ficha HTML + datos para hidratar |
| `/es/dinastia/:slug` | Ficha HTML + datos para hidratar |
| `/es/territorio/:slug` | Ficha HTML + datos para hidratar |
| Fichas con `?atlas=1` | Shell del Atlas; el arranque cliente también comprueba este parámetro |
| `/es/historia/:slug`, desafíos, portadas, catálogos y páginas informativas | Aplicación dinámica existente |
| Rutas antiguas de entidades sin `/es` | Compatibilidad dinámica existente |
| Ruta pública inexistente | Sin HTML generado; las reglas ya no la convierten indiscriminadamente en la portada |

`vercel.json` prioriza `atlas=1`, asigna las rutas públicas a sus archivos `index.html` y mantiene las entradas SPA explícitas. No se modifica `dist/index.html`. No hay funciones SSR ejecutándose en el servidor: todos los documentos se generan al compilar.

Las historias interactivas y sus recorridos permanecen en el Atlas. Tampoco se altera su motor, cartografía, datos históricos, retratos, filtros ni desafíos. Las fichas conservan sus límites de presentación existentes: por ejemplo, la dinastía muestra inicialmente 36 miembros y activa búsqueda y ampliación con JavaScript. Con JavaScript desactivado se puede leer el contenido inicial y seguir enlaces; los controles interactivos requieren JavaScript.

## Pipeline y comprobación

`npm run build` ejecuta:

1. `prebuild`: cinco auditorías y generación de sitemaps, índices y JSON.
2. `vite build --manifest`: compilación del cliente y copia de recursos.
3. `scripts/prerender-ssg.mjs`: compilación temporal del renderizador, lectura de datos y escritura de fichas en `dist/es/.../index.html`.
4. `scripts/audit-ssg.mjs`: comprobación de todas las fichas escritas contra el sitemap y los JSON fuente.

La auditoría falla si falta una ficha, el contenido es una pantalla de carga, hay metadatos incorrectos, falta CSS, los datos incrustados divergen o aparecen páginas generadas fuera del alcance. También comprueba que el shell dinámico permanece vacío. Los informes quedan en `dist/ssg-report.json` y `dist/ssg-audit.json`; no es necesario editarlos ni subirlos como código fuente.

Para inspeccionar una muestra después del build:

```sh
npm run ssg:sample
npm run audit:ssg
EADE_SSG_SAMPLE=.ssg-sample node --import ./tests/jsx-loader.mjs --test tests/hydration.test.mjs
```

El último comando utiliza sintaxis de variables de entorno de macOS/Linux. La muestra contiene 12 personas, 4 dinastías y 4 territorios, en `.ssg-sample/`, sin reemplazar el resultado publicable. Se puede leer directamente su HTML sin iniciar un servidor. GitHub Actions ejecuta también esta muestra y su hidratación después del build.

- `npm run prebuild`, ejecutado por `npm run build`: **correcto**.

- Dinastías: **16 historias y 17 conexiones, 0 errores**. Sucesiones: **55 relevos y 4 crisis, 0 errores**. Coronas: **52 accesos y 8 uniones, 0 errores**.
- `npm run build`, con Vite 8.2.1: **correcto**. Se mantiene el aviso existente de un bundle del Atlas superior a 500 kB.
- Sitemap: **2997 URLs**. SSG: **2973 fichas** — 2277 personas, 470 entradas dinásticas y 226 territorios. Las otras 24 URLs permanecen fuera del alcance de esta generación.

La validación se realiza sobre archivos y DOM simulado, sin revisión visual ni servidor local. Comprueba también el color calculado del acceso al Atlas y la inclusión de hojas de estilo. No sustituye una comprobación visual en un navegador real. No se han publicado cambios ni verificado una respuesta HTTP de Vercel: las reglas de alojamiento se han comprobado localmente. Tras el despliegue, conviene comprobar una ficha, la misma URL con `?atlas=1` y una historia en el alojamiento real. El HTML estático facilita el acceso al contenido, pero no garantiza indexación ni posiciones en buscadores.
